production · private code p&l platform

A defensible monthly P&L, owned end to end

A dedicated Postgres P&L database fed by Amazon SP-API, Shopify and Sheets, with FX conversion and three-way matching for the month-end close.

Role
sole data engineer · Timeline: Aug 2025 – Sep 2026 · Team: 1
Stack
PostgreSQL · BigQuery · Amazon SP-API · Shopify API · Python
Code
private (company IP). Walkthrough on request: email me

01Problem

The company's monthly P&L was a founder-built spreadsheet that was not accurate enough to run a business on. Revenue, cost of goods and fees came from different systems and were reconciled by hand.

The task was to replace it with a process someone owns, that can be defended line by line, and that closes on a fixed monthly cadence.

02Constraints

  • Three sources with different shapes: Amazon SP-API, Shopify and Google Sheets.
  • Multi-currency sales, so FX conversion has to be explicit and repeatable.
  • Month-end deadlines set by the accountant.
  • One engineer, who is also the person closing the month.

03Architecture

04Key decisions

  • A dedicated Postgres database for the P&L, separate from the operational apps, so the numbers have one owner and a stable schema.
  • dbt-style layering (staging, then marts) so every P&L line traces back to a source row.
  • Three-way matching of purchase order, goods receipt and invoice, so cost lines are backed by documents and not by estimates.

06Results

The monthly statement moved from an inaccurate self-built process to an owned, repeatable cadence.
