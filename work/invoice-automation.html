production · private code invoice automation

Matching ~1,000 monthly transactions to invoices with an LLM

A production pipeline that classifies which transactions need an invoice, then matches each one to its PDF with confidence-scored Claude API screening.

Role
sole data engineer · Timeline: 2026 · Team: 1
Stack
GCS · Cloud Scheduler · Gmail API · Claude API · Python
Code
private (company IP). Walkthrough on request: email me

01Problem

A small e-commerce company books roughly 1,000 transactions a month. About a quarter of them need a supporting invoice, and someone has to find the right PDF in a Gmail inbox and link it to the transaction before the month can be closed.

That linking was paid-for accountant time and a recurring drain on the founder's. It was also the step that made month-end slow, because nobody could close the books until every invoice was matched.

02Constraints

  • Solo build, startup budget: no new platform to run, no per-seat tooling.
  • Messy inputs: invoices arrive as PDFs by email with inconsistent vendor names and layouts.
  • Audit trail: every match decision has to be reproducible months later.
  • Hard deadline: the accountant needs the month matched on a fixed schedule.

03Architecture

04Key decisions

  • Screen first, match second. Only ~25% of transactions need an invoice, so the expensive matching step runs on a quarter of the volume.
  • A confidence score on every match, and the verdict routes the file. Low-confidence matches never land silently in accepted/; they go to trash/ where they can be reviewed.
  • Hive-style date partitions over a flat bucket. Backfills and audits become a path prefix instead of a query, and re-running a month cannot overwrite another month.

05Data model · Storage layout

invoices-bucket/
  raw/                    landing zone for fetched PDFs
  accepted/YYYY-MM/       matched, high confidence
  trash/YYYY-MM/          rejected, low confidence
  backups/  config/

06Results

~1,000transactions / month
~25%need an invoice
3partitions: raw / accepted / trash

Replaced accountant fees for transaction-to-invoice linking, and freed founder time at every month-end.

07What I'd do next

  • A review queue for mid-confidence matches, so a human confirms the uncertain ones instead of the script discarding them.
  • Per-vendor precision tracking with an alert when a vendor's match rate drifts, which would catch a changed invoice layout early.
