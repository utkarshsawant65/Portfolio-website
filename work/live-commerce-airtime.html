public repo live commerce airtime intelligence

Tying every order to the broadcast minute that drove it

A governed dbt + Snowflake + Power BI data product that attributes orders to broadcast airtime and measures live-commerce performance.

01Problem

Live-commerce retailers sell through broadcast, backed by an online shop and an app. A presenter shows a product in a time window and orders spike across every channel at once. The business question is which product, presenter and time slot earns the most per minute of air.

Standard retail models cannot answer it, because nothing ties an order to the segment that caused it. This project models that mechanic end to end and measures revenue per broadcast minute, conversion lift and return-rate intelligence.

02Constraints

  • No public dataset carries a broadcast or airtime dimension, so the data is synthetic by design. Generating it means the airtime-to-sales correlation is known and the attribution logic can be checked against ground truth.
  • Runnable offline before a Snowflake account exists.
  • BI reads from MARTS only. No dashboard or ad-hoc query touches staging or raw.
  • Every KPI is defined once, in one catalog.

03Architecture

04Key decisions

  • Micro-batch ingestion, not Kafka. This is an analytical workload with minutes-fresh KPIs, not sub-second events. A streaming bus would be a second distributed system to run for no analytical gain. Streams + Dynamic Tables are built as the upgrade path.
  • Land the semi-structured feed as VARIANT. Schema-on-read decouples ingestion from schema, so a source adding or renaming a field never breaks the load.
  • Quarantine bad rows instead of dropping them. Invalid rows go to a quarantine model with a failure reason, which makes data quality observable and backfillable.

05Data model · Star schema and attribution

dims   dim_date · dim_time_minute · dim_product (SCD2)
       dim_presenter · dim_channel · dim_show
facts  fact_order_line (incremental) · fact_airtime_segment
       fact_returns · fact_traffic
attr   int_orders_attributed_to_airtime
       order_time in [start, end + lag], last-touch tie-break,
       unmatched orders -> segment -1 (organic)

07What I'd do next
